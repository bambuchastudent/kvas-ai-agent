# Квас 1.0.4

Бренд: **Жижа**.

## Главное изменение

Добавлена специальная страница для репоста в Telegram:

```text
https://bambuchastudent.github.io/kvas-ai-agent/v1.0.4/
```

Её заголовок:

```text
Квас Жижа для ИИ-агента
```

Для страницы подготовлена отдельная карточка на основе фотографии домашнего кваса. В HTML зафиксированы Open Graph-поля, чтобы мессенджер получил нужные заголовок, описание и изображение.

## Что добавлено

- `share/index.html` — страница для репоста;
- `share/assets/card-1.0.4.b64.part01` … `part10` — проверяемый источник JPEG-карточки, разбитый на небольшие части;
- `share/telegram-message.txt` — готовый текст сообщения;
- `.github/workflows/pages.yml` — сборка, проверка и публикация через GitHub Pages;
- `docs/telegram-sharing.md` — правила репоста и обновления карточки;
- упрощённый README со ссылкой для Telegram в самом начале.

Workflow склеивает Base64-части, декодирует JPEG и проверяет:

- достаточный размер файла;
- сигнатуру JPEG;
- наличие завершающего маркера JPEG;
- наличие `og:title`, `og:image`, `og:url` и нужного заголовка в HTML.

## Почему отдельная страница

Обычная ссылка на GitHub-репозиторий использует карточку, которую формирует GitHub. Содержимое README не даёт надёжно управлять заголовком и изображением Telegram-превью.

Страница GitHub Pages позволяет явно задать:

- `og:title`;
- `og:description`;
- `og:image`;
- `og:url`;
- Twitter Card-поля как дополнительный совместимый набор метаданных.

## Что нужно сделать один раз

Если GitHub Pages ещё не включён:

```text
Settings → Pages → Build and deployment → Source → GitHub Actions
```

После этого workflow **Deploy Telegram share page** будет публиковать карточку автоматически.
