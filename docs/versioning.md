# Версии КВАССИСТЕНТА

Базовая точка новой линии: **1.1.0**.

Текущий релиз: **1.1.1.1 · единиц: 4**.

## Правило

После версии `1.1.1` каждый новый релиз получает ещё один сегмент `.1`:

```text
1.1.1       · единиц: 3
1.1.1.1     · единиц: 4
1.1.1.1.1   · единиц: 5
1.1.1.1.1.1 · единиц: 6
```

`ones_count` — количество сегментов версии, которые равны `1`.

Каноническая версия хранится в:

```text
release/version.json
```

## Создание следующей версии

```bash
npm run next-release
```

Скрипт:

1. берёт `current`;
2. добавляет `.1`;
3. пересчитывает количество единиц;
4. обновляет `previous`, `current`, `display` и `next`;
5. синхронизирует manifest, gallery, package metadata и текстовый указатель версии;
6. создаёт заготовку release notes, если её ещё нет.

Git tag и GitHub Release используют точную строку:

```text
v1.1.1
v1.1.1.1
v1.1.1.1.1
```

`package.json.version` остаётся совместимым с SemVer. Точная пользовательская версия хранится в полях `kvassistentRelease` и `onesCount`.

## Бренд-чеклист каждого релиза

Перед выпуском следующей версии обязательно проверить:

- на главной есть заголовок **«ТВОЙ ЛИЧНЫЙ КВАССИСТЕНТ»**;
- явно разделены роли: **ИИ управляет процессом, человек делает квас своими руками**;
- **Жижа** названа домашним квасом и выделена как ключевой бренд;
- README, metadata для репоста и карточка говорят одно и то же;
- pipeline проверяет канонический заголовок и формулировку ролей.
- каждая языковая карточка целиком локализована: название, описание и кнопки написаны на выбранном языке, а элемент содержит правильный атрибут `lang`;
- pipeline отдельно проверяет кнопки для русского, английского, испанского, немецкого и упрощённого китайского.

Полный контракт бренда хранится в [`docs/branding.md`](branding.md).
